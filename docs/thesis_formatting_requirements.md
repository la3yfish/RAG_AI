# Diploma Thesis Formatting Requirements (Guideline)

> **Scope note:** Universities often publish their own template and formatting rules for a thesis / VKR.  
> Where local (university) rules conflict with the standards below, **follow the university template first**.  
> Items marked **[Verify locally]** are common in practice but are *not guaranteed* to be mandated by the cited GOST standards.

---

## 1) Page setup and typography

- **Font**: Times New Roman, 12–14 pt **[Verify locally]**.
- **Line spacing**: 1.5 **[Verify locally]**.
- **Margins** **[Verify locally]**:
  - Left: 30 mm
  - Right: 10–15 mm
  - Top / bottom: 20–25 mm
- **Paragraphs**: consistent indentation and spacing; avoid manual alignment using spaces/tabs; use styles (Heading 1/2/3, Normal) **[Verify locally]**.

---

## 2) Pagination, headings, and sectioning

- **Numbering**: continuous Arabic numerals.
- **Title page**: usually not printed with a page number, but counted in total page count **[Verify locally]**.
- **Headings**:
  - Bold; no period at the end of the heading line **[Verify locally]**.
  - Each major section/chapter starts on a new page (e.g., Introduction, Chapter 1, Conclusion) **[Verify locally]**.

---

## 3) Figures, tables, and formulas

- **Figures and tables**:
  - Must be referenced from the text (e.g., “see Table 2”, “Figure 3 shows…”).
  - Must have a **caption** and **numbering** (usually within chapter or overall; choose one scheme and keep it consistent).
- **Placement**: near the first reference in the text (or on the next page), avoiding “orphaned” captions.
- **Quality**: diagrams must remain readable when printed; avoid tiny fonts in figures.

> For general requirements to text documents and presentation of tables/figures, use **GOST R 2.105-2019** as a baseline.

---

## 4) Typical thesis / VKR structure (recommended)

1. **Title page** (per university template).
2. **Abstract / Annotation**.
3. **Table of contents**.
4. **Introduction**: relevance, goal, objectives, object/subject, methods.
5. **Chapter 1 — Theoretical/Analytical**: domain analysis, related work, justification of choices.
6. **Chapter 2 — Design/Methodology**: system architecture, data model, key design decisions, diagrams (UML/C4/ERD).
7. **Chapter 3 — Implementation/Experimental**: implementation notes, testing, experiments, evaluation results.
8. **Conclusion**: summary of achieved objectives, limitations, future work.
9. **References** (bibliography).
10. **Appendices**: ToR/TZ, code listings, test protocols, additional tables/figures.

---

## 5) References and citations (bibliography)

- **Bibliographic descriptions (for the reference list)**: use **GOST 7.1-2003** (rules for bibliographic descriptions).
- **In-text citations / footnotes / references to sources**: use **GOST R 7.0.5-2008** (bibliographic references/citations).
- Choose one consistent citation style (e.g., numeric [1], [2]… or author-year) permitted by your university; map it to the applicable GOST requirements **[Verify locally]**.

---

## 6) Technical artifacts often expected in CS/IT theses (recommended set)

For an applied software engineering thesis, the following artifacts are commonly expected (university-specific):

- **Technical assignment / Terms of Reference (TZ/ToR)**: if required, structure it using **GOST 34.602-89**.
- **Architecture diagrams**: C4 (Context/Container/Component) or equivalent.
- **UML diagrams**: Use Case, Class, Sequence (as needed).
- **Data model**: ERD and/or relational schema.
- **Testing package**: test plan + test cases + test results tables; performance metrics and acceptance criteria.
- **Experiment results**: tables/plots comparing variants (e.g., RAG pipeline configs), plus interpretation.

## 8) What you should confirm with your university (checklist)

- Exact **template** for the title page and front matter.
- Mandatory font/size/spacing/margins.
- Whether chapters are numbered “Глава 1/2/3” or “1/2/3”.
- Reference style (numeric / author-year) and specific GOST variant required by your кафедра.
- Mandatory set of diagrams/appendices and whether a printed code listing is required.
